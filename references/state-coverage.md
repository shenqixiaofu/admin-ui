# 状态覆盖：四种状态怎么写

主文件讲了「四态齐不齐」，这里讲每一态具体长什么样。判断顺序永远是：**先判断状态，再渲染内容**。

## 判断顺序（不要按 if 嵌套写）

```
1. 没有权限？        → 权限态（这是最外层，先挡住）
2. 正在加载？        → 加载态（首次加载才占位，后续刷新不要）
3. 出错了？          → 错误态（带原因 + 重试）
4. 数据为空？        → 空态（分「真没有」和「筛没了」）
5. 有数据            → 正常渲染
```

**顺序不能乱**：先判断空再判断错误，会把「请求失败」显示成「暂无数据」，用户会以为数据被删了，去找运维。这是后台最常见的一个假象。

## 一、加载态

### 首屏加载 vs 后续刷新，处理方式不同

| 场景 | 做法 |
|---|---|
| 首次进入页面 | 骨架屏，**保留表格的表头与列宽** |
| 筛选/翻页/排序 | 只盖列表区域，半透明遮罩或顶部细进度条 |
| 局部操作（点一行里的按钮） | 只禁用那个按钮并显示进行中 |
| 自动轮询刷新 | **不要任何 loading 提示**，静默替换；可以用一个小圆点在角落表示「刚刚更新」 |

**骨架屏必须跟真实布局同构**：表头、列宽、行高都要对上。骨架画成三个大色块，加载完突然变成 8 列表格，视觉跳动比直接白屏还难受。

**全屏遮罩只在一种情况下可用**：整页数据互相关联且互相依赖（比如一个详情页的所有区块都来自同一个接口）。列表页永远不该用。

## 二、空态：必须分两种

这是后台最高频的偷懒点，也是投入产出比最高的一处修正。

### A. 真的没有数据

```
[图标]
还没有标签
标签用来给会员分组，先建一个试试。
[新建标签]
```

三件套：**说明现在是什么都没有 + 一句为什么需要它 + 一个下一步动作**。

### B. 筛选把数据筛没了

```
[图标]
没有匹配「2024-11-09」「已归档」的结果
[清空筛选]
```

三件套：**回述用户用的条件 + 一句「共 N 条数据但都不匹配」+ 清空入口**。

回述条件很重要 —— 用户经常忘了自己半小时前点过什么筛选。

### 判断当前是哪种

```js
const isEmptyByFilter = hasActiveFilters(filterState)
```

只要有任何一项筛选条件生效，就是 B；否则是 A。**不要靠数据长度判断**。

### 空态不要做的三件事

- 不要放一个大插画占半屏。后台用户需要的是信息密度，不是情绪。
- 不要在空态里塞广告或引导注册。
- 不要隐藏操作按钮。空态时「新建」恰恰是唯一的必要操作。

## 三、错误态：要分级，不要笼统说「加载失败」

| 类型 | 页面写什么 | 给什么动作 |
|---|---|---|
| 网络断开 / 超时 | 网络连接失败，请检查网络 | 重试 |
| 服务端 5xx | 服务暂时不可用（错误码 502） | 重试 + 复制错误码 |
| 业务错误（4xx 带 message） | **直接显示后端返回的 message** | 按 message 给动作 |
| 401 / 登录过期 | 登录已过期 | 跳登录，且**带回跳地址** |
| 403 / 无权限 | 没有权限执行此操作 | 说明联系谁，或给申请入口 |
| 未知 | 未知错误 + 错误码 + 请求 ID | 复制诊断信息 |

**后端给了 message 就直接用**，不要统一替换成「操作失败」。后端辛苦写的「该标签已被 3 个会员使用，无法删除」，被前端换成「操作失败」是纯粹的浪费。

**错误码要显示出来**。用户报障说「502」，比说「打不开」有用一百倍。有请求 ID 就一起给，并且给个复制按钮。

## 四、权限态

**权限不是空数据，也不是错误**。它是独立的一态，因为用户要采取的动作完全不同：

- 空数据 → 「去建一个」
- 无权限 → 「去找谁开」

三种粒度，选一种实现，不要混：

1. **菜单级**：没权限的导航项不显示（最省事，但用户会问「功能去哪了」）
2. **页面级**：能进去，显示「无权限查看此页面」
3. **按钮级**：页面能看，操作按钮禁用 + tooltip 说明原因

**推荐 2 + 3 组合**：页面级给说明，按钮级给原因。菜单级隐藏只用于「这个用户永远用不到」的模块。

按钮级禁用**必须带原因**，不能只是灰掉。灰掉不加说明，用户唯一的结论是「这破系统又坏了」。

## 五、状态叠加怎么排

真实情况经常同时满足两个条件，比如「加载失败」+「上次有数据」。

规则：**保留上一次的数据，在顶部挂一条错误提示**。

```
[⚠ 刷新失败，显示的是 3 分钟前的数据]  [重试]
（下面是上一次的数据）
```

这比清空表格只显示错误好得多 —— 用户至少还能看到内容，也能理解为什么数字是旧的。

**只有首次加载失败时才用整块错误态**（因为没有旧数据可保）。

## 六、一个页面里的状态数量

一个包含「主表 + 侧边统计 + 底部日志」的页面，是三个独立的加载单元，各自有各自的四态。

**不要用一个全局 `loading` 变量控制整页**。侧栏统计慢 2 秒，主表就得等它，这在用户眼里就是「这个系统很卡」。

拆成独立的 loading 与 error，各自渲染各自的骨架。
