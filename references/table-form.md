# 表格、筛选、批量、表单

后台四个高频部件，每个都有固定几个坑。

## 一、表格

### 列宽

- **给列设宽度，或者用 `table-layout: fixed`**。默认的 auto 布局会让列宽随内容抖动，翻页时整张表左右乱颤，扫读成本直接翻倍。
- **按内容类型分配宽度**：ID/时间/状态这类定长内容给固定宽度；名称/备注这类可变内容给弹性宽度。
- **不要把 12 列都塞进来**。判断标准：不看这一列能不能完成当前任务？能就默认隐藏，放进「列设置」。

### 对齐

- **数字右对齐 + `tabular-nums`**，否则位数不同无法竖着扫。
- **文本左对齐**。
- **状态、操作中/右对齐**。
- **表头对齐跟数据一致**。表头左对齐、数字右对齐是最常见的错位。

### 排序

- **可排序的列必须有视觉标记**（升/降箭头），且要区分「未排序」和「升序」两种状态。
- **只给真正有意义的列加排序**。给「备注」加排序，用户点了会发现排出来的结果毫无意义。
- **默认排序要可见**。默认按时间倒序就在时间列上显示降序标记，不要默默排。

### 行

- **行高 44–56px**。低于 44 点击目标太小；高于 56 一屏看到的数据太少。
- **斑马纹和分隔线二选一**，不要都用。
- **hover 高亮整行**，不只是文字变色。
- **操作列固定宽**，不随内容变化。操作多时收进「…」，不要横向排 5 个文字链接。

### 什么时候不用表格

- 每条数据有图、有描述、有多行属性 → 用卡片列表。
- 数据项在 3 个以内且强调对比 → 用描述列表。
- 需要横向对比很多字段 → **还是用表格**，卡片做不到。

## 二、筛选

### 位置

- **筛选器在表格上方，与表格同宽**。
- **常用筛选露出，低频塞进「更多筛选」**。
- **筛选条件超过 5 个时，分成两层**：第一层是高频的 2–3 个，第二层收起来。

### 生效时机（选一种，全文统一）

| 方式 | 适用 | 代价 |
|---|---|---|
| **即时生效**（改动即查询） | 数据量小、查询快（<300ms） | 快速连点时打出一串请求，需要防抖 |
| **点「查询」按钮** | 数据量大、查询慢、条件多 | 用户改了条件忘了点，看到的还是旧数据 |
| **混合**：文本输入用按钮，下拉/日期用即时 | 大多数后台 | 需要一次说明，用户能学会 |

**不要在同一页里两种都用**。有的筛选项立即生效、有的要点按钮，用户永远在猜。

用按钮模式时，**条件改了但没查询，要给标记**（按钮变色 / 显示「有未应用的筛选」）。

### 已选条件必须可见可删

- 筛选生效后，在表格上方显示**条件标签**，每个可单独 × 掉。
- 提供「清空全部」。
- 这是空态 B 的配套：用户看到「没有匹配结果」，一眼能看到是哪个条件卡的。

### 状态进 URL

```
/list?status=archived&sort=created_at:desc&page=3&size=20
```

刷新、分享、后退都要还原。**不要只存 component ref**。

### 改条件时页码回 1

在第 8 页把筛选从「全部」改成「已归档」，结果只剩 2 页 —— 如果不回 1，用户看到空表，然后以为没有数据。

## 三、批量操作

### 全选的语义陷阱

「全选」到底是：

- **A. 选中当前页这 20 条**
- **B. 选中符合当前筛选条件的全部 128 条**

这是后台最危险的歧义。必须显式：

```
☑ 已选当前页 20 条
   [选择全部 128 条符合条件的数据]
```

或反过来：

```
☑ 已选 128 条（全部符合条件）
   [只选当前页 20 条]
```

**默认必须是 A**（当前页）。用户点表头的全选框，心理预期是「这一屏」。跨页全选必须是一次额外点击，且数量必须显眼。

### 已选状态

- **常驻显示「已选 N 条」**，浮在表格顶部或底部固定条。
- **必须有「取消选择」**。没有出口的选择状态是最容易误操作的。
- **翻页要保持已选**，否则用户没法跨页选。保持时要显示「已选 45 条（含 2 个其他页）」。
- **筛选变化时清空已选**，并提示「筛选已变更，已清空选择」。保留会导致删掉用户看不见的数据。

### 批量操作的确认

```
将删除 45 条标签
其中 3 条已被会员使用，删除后这些会员会失去标签
[取消]  [删除 45 条]
```

三件事缺一不可：**数量、影响、后果**。确认按钮上重复数量，比只写「确定」安全一个数量级。

## 四、表单

### 分组

- **超过 8 个字段就分组**，每组一个标题。
- **组标题说明「这一组在配什么」**，不要用「基础信息」「高级设置」这种不解释的标签。
- **一列到底，不要两列并排**，除非字段之间有明确配对关系（开始时间 / 结束时间）。

### 校验

- **失焦校验单个字段**，提交时全量校验。
- **不要在输入过程中报错**。用户输入 `1` 的时候提示「必须是两位数」，是在他还没写完时打断他。
- **错误信息说清怎么改**：「手机号需要 11 位」比「格式错误」有用。
- **错误显示在字段下方**，红色边框 + 文字。不要只变边框，色弱用户看不出。

### 必填与默认值

- **必填用文字标注**（「必填」或「必选」），不要只用红色星号。
- **能给默认值就给**，尤其是有 90% 用户会选同一个的选项。
- **默认值要说明是默认**，不然用户以为是系统算出来的。

### 提交

- **请求中：按钮 disabled + 文案变「保存中…」**。
- **失败：保住已填内容**，只在顶部或字段旁提示错误。
- **成功后给明确反馈**：留在原页显示「已保存」并更新数据，或返回列表并高亮刚改的那一行。**不要只是弹个 toast 就完事**。
- **离开拦截**：有未保存修改时，路由切换要拦截并询问。

### 长表单

- **分步骤**（向导）适用于有先后依赖的表单；单纯字段多就分组，不要做成三步向导。
- **步骤条要显示当前在几步中的第几步**，不要只有一个「下一步」。
- **允许回退到上一步**，且保住已填内容。

## 五、分页

- **显示「第 3 / 12 页，共 238 条」**，不是只有「共 238 条」。
- **每页条数可改**，20 / 50 / 100，且记进 URL。
- **页码支持跳转**（输入框），数据超过 10 页时必要。
- **总数用「约」**：`count(*)` 在大表上很贵，用近似值并标注「约 238 条」比让接口卡 3 秒好。
- **不要用无限滚动**。后台用户需要定位和回退，无限滚动两者都做不到。
