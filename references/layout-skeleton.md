# 后台骨架选型

骨架定错，后面每个页面都在跟它对抗。选型只看三个问题：**一级导航几项、有没有「对象」、用户是来看还是来干活**。

## 一、先判断这是哪种后台

| 类型 | 特征 | 骨架 |
|---|---|---|
| **工具型** | 用户每天进来完成固定任务：发内容、审单、回工单 | 侧栏 + 列表，首屏是待办而非图表 |
| **数据型** | 用户来看数、导出、对账 | 侧栏 + 大表格 / 看板，筛选器是主角 |
| **配置型** | 低频，进来改设置就走 | 顶栏 + 分组表单，不需要侧栏 |
| **对象型** | 围绕「一条」东西工作：邮件、工单、会话 | 双栏（列表 + 详情）或三栏 |

**判错的代价**：把配置型做成侧栏后台，用户一年进两次，每次都要重新认路；把对象型做成单页跳转，用户每次看详情都要返回列表，一天多点两百次。

## 二、一级导航

- **≤ 5 项用顶栏，> 5 项用侧栏**。5 项以内做侧栏，左边一条永远空着的竖条很浪费。
- **一级导航上限 7 项**。超过就分组，不要靠缩小字号和图标硬塞。
- **顺序按使用频率，不按业务模块**。首页、订单、用户、配置是常见顺序；把「系统设置」放第一位是把自己的目录结构当成了用户的路径。
- **当前项要双重标记**：底色 + 文字色/字重。只靠颜色，色弱用户分不出；只靠加粗，扫视时找不到。
- **不要做二级悬浮菜单**。悬停展开的二级菜单在触屏和键盘上都难用，改成一级导航 + 页内 tab，或者侧栏内可折叠分组。

## 三、尺寸（直接用，不要每次重新商量）

| 项 | 值 | 理由 |
|---|---|---|
| 侧栏宽度 | 200–240px 固定 | 用百分比会在宽屏上撑成一条走廊 |
| 顶栏高度 | 48–56px | 低于 48 控件挤，高于 56 浪费纵向空间 |
| 内容区左右内边距 | 24–32px | 小于 24 贴边，大于 32 在 1280 屏上浪费 |
| 表格页内容宽度 | 撑满 | 表格列多，缩窄只会让列被压扁 |
| 表单页内容宽度 | 640–800px | 再宽，一行读到头要转头 |
| 抽屉宽度 | 400–560px | 小于 400 装不下表单，大于 560 不如用整页 |

**侧栏折叠只在一种情况下做**：内容需要宽屏且用户会长时间停留（画布、图表、代码编辑）。日常列表页不需要折叠，多一个按钮就是多一个认知负担。

## 四、工作台首页：最容易做错的一页

后台首页最常见的长相是「四张指标卡 + 一张折线图」，而用户进来其实只想看**今天要做什么**。

按这个顺序排，从上到下：

1. **异常与待办**：待审核 3、失败任务 1、超期工单 2。每条可点进对应列表，且带筛选条件。
2. **最近操作**：我刚改过的、我创建的。用户回来找的是「刚才那条」。
3. **趋势**：折线、漏斗、分布。这是给管理者看的，不是给操作者看的。
4. **指标卡**：放最上面最显眼的位置，往往只是好看。

**判断依据**：如果这个页面的用户是**操作者**，1 和 2 必须在首屏；如果用户是**管理者**，3 和 4 才有意义。两种人用同一个后台时，用角色切换或 tab 分开，不要混在一页里都放一半。

## 五、列表 ↔ 详情的三种走法

| 方式 | 适用 | 代价 |
|---|---|---|
| **跳转整页** | 详情内容多、需要独立地址分享 | 返回要还原状态（见 SKILL.md「位置」） |
| **右侧抽屉** | 详情轻量，看完就关 | 内容多时滚动很难受，深度嵌套会套娃 |
| **双栏常驻** | 高频来回切换（工单、邮件） | 占用横向空间，1280 屏以下会挤 |

**不要三种混用**。同一个后台里，两个模块用抽屉、三个模块用跳转，用户永远猜不到点下去会发生什么。

## 六、响应式（后台也要，但不是全尺寸）

后台主要跑在 1440 和 1920，但要保证 1280 可用：

- **1280 是底线**，低于它允许横向滚动，不要为了塞进 1024 把表格压成竖排。
- **侧栏在 1280 以下收成图标条**（56px），不要做成抽屉——抽屉每次打开都要一次额外点击。
- **表格在窄屏优先隐藏次要列**，不要把所有列都挤成两行文字。哪些是可隐藏的次要列，按「不看它能不能完成任务」判断。
- **不要在后台做移动端适配到可操作的程度**。真需要手机上用的功能，单独做一个精简视图，而不是把 20 列的表格压成卡片流。
