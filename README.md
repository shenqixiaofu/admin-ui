# admin-ui

后台 / 工作台的**结构与流程**纪律。把「后台不好用」拆成三件可检查的事：

1. **这个状态有没有出口？** —— 加载、空、出错、无权限，四态齐不齐
2. **用户点下去之前，知不知道会发生什么？** —— 影响面、可撤销、二次确认
3. **离开再回来，还找不找得到位置？** —— 筛选、排序、页码、勾选

## 它不管什么

**不管视觉值**。色值、字号、圆角、阴影、间距、动效时长，一律按项目已有 token，没有就交给 [ui-discipline](https://github.com/shenqixiaofu/ui-discipline)。

两边同时生效：**结构按本技能，色值字号回 ui-discipline**。

## 什么时候用

- 新建后台页面、重排信息架构
- 重做表格、表单、筛选、批量操作
- 给列表补空态 / 加载 / 出错 / 无权限
- 把老后台改得好用
- 后台 UI 评审

**不适用**：纯营销页、落地页、C 端 App 界面。落地页靠主角和留白，后台靠网格和秩序，两套判据不要互相套。

## 目录

```
SKILL.md                        主文件：核心判据、硬规则、反模式、自检、改造流程
references/
  layout-skeleton.md            骨架选型：几项导航、有没有「对象」、看还是干活
  state-coverage.md             四态怎么写：判断顺序、空态两分、错误分级、状态叠加
  table-form.md                 表格、筛选、批量、表单、分页
  legacy-migration.md           老后台改造：分级、盘点、改一页的流程
scripts/
  audit.py                      机械自检，只报缺什么
```

## 自检

在项目根目录：

```bash
python3 <skill>/scripts/audit.py .
python3 <skill>/scripts/audit.py . --json
```

输出会列出每个页面的四态覆盖情况，以及危险操作文案、URL 状态同步、hover-only 操作、`aria-label`、表格列宽、分页位置这些全局指标。

**只报数字，不判断对错**。数字背后的取舍由人定。

## 和 oil-ui 的关系

[oil-ui](https://github.com/oil-oil/oil-ui) 管「放开做，好看」——探索方向、生成对比页、按截图打磨。
本技能管「收口，好用」——方向定了之后，把状态、流程、可达性补齐。

两者不重叠：探索阶段让位给 oil-ui，收口阶段回到本技能。
